# 自瞄算法优化记录

更新：2026-10-29。工作区：`sp_vision_25`、`bevy_robomaster_simulator`。

## 当前目标与约束

1. 高速移动、急变向时保持跟踪，降低预测滞后和丢失后的恢复时间。
2. 追击过程中双方变速时提高有效打击能力，正确处理自车运动。
3. 改进自瞄门控：减少选板来回切换、角度跳变和开火抖动；平滑不能以额外滞后为代价。
4. 对齐图像/姿态时间、云台操控、发弹与预计命中时间，区分控制预测和射击判定。
5. 模拟器真实环境调参暂缓，当前优先算法。真实画面验收由用户进行。

最小修改，沿用原代码风格；保留已有有效功能，不整体替换识别、跟踪或弹道框架。
最终须在项目内留下相对上游的优化总结，对应实际 Git 差异、参考来源和验证结果。
中心度设想可以补全、比较后择优，不要求照搬任何仓库；以可复现收益决定保留哪些改动。
不要随意修改模型权重、相机/装甲尺寸、命中碰撞范围、弹速、PID 或物理参数来制造收益。
`bevy_robomaster_simulator` 可以修改，但仅限算法闭环、操控/开火时序确实需要的部分。
保持 CUDA/OpenVINO 共用识别后处理，启动脚本使用 shell，可从 fish 调用。
新增约束：改坏或随意重写原本有效的逻辑/设计是大忌。优先定位具体缺陷，条件触发的补偿保留原路径回退；
每项优化单独对照，公开正常工况的数值变化与取舍，不以“新设计”本身作为保留理由。
最新对比方案：上游 A0、仅修明确缺陷的 A1、优化候选 B 三版分离，主结论用完整图像闭环的 A1/B 配对验证。
单项消融只解释贡献；同后端/原参数/原物理条件，多独立用例，固定时长，兼看命中/秒与中心度得分/秒。
协议详见 `sp_vision_25/OPTIMIZATION.md`；当前 `./sim.sh report` 尚未实现这一完整主对照，不得误标。

## 中心度加权评价的设想

用户提供的参考图片：`0.jpg` 至 `10.jpg`（本地资料，未随仓库提供）。
开火权重的含义已澄清：优先优化开火时机/门限，不是修改控制器代价函数。

- 在命中时刻，按装甲板局部平面的半宽、半高归一化实际落点，计算中心度。
- 每发加权得分为 `hit * centrality`；脱靶为零，分母包含所有已发射弹丸。
- 同时记录普通命中率、命中弹平均中心度、加权命中率、命中数/秒、加权得分/秒、发射数。
- 禁止用少开火单独提高每发分数而忽略有效打击效率；不得用未来真值辅助在线决策。
- 在线开火只能使用观测/估计状态、实际云台姿态和预测落点，实际碰撞用于离线验收。
- 配对固定种子、完整弹丸结算；另用未参与调参的种子验证，重复运行不算独立样本。

图 9 报告主场景加权率 33.8% → 45.3%，但自车移动为 89.3% → 87.9%。
图 10 同时提到短补偿和角点噪声改动。仅有图片，尚未取得这些实验的代码、公式和原始配对日志；
不能将 R4 全部收益归因于中心度，也不能视作当前工作区已经实现/通过验收。

- 曾增加角加速度拟合，但在匀速输入中误触发并减少有效射击，现已删除；恢复原角速度预测，不继续叠加修补。
- 自车运动补偿与原生弹丸继承底盘速度对齐；未修改原生弹速、重力、装甲碰撞范围或 PID 增益。
- 控制解和可射击窗口分开；按预测装甲尺寸约束 yaw/pitch，使用内外窗口滞回和最短角差。

- 处理期间的自身加速度在瞄准副本上补偿，与开火瞬间的弹丸继承速度对齐；发弹原点/方向使用实际枪口世界变换。
- `./sim.sh test` 通过：ABI/同步/几何、两轴门控、时序、九类机动场景回归，以及 C++ Solver 到原生 PID/发弹/Avian 碰撞的联合验证。
- 独立消融中，90°变向提前量位置误差约 297 → 158 mm（2 mm/30 Hz）；同条件变速旋转约 67 → 36 mm。
